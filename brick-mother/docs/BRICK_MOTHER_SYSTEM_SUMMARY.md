# Brick Mother 系统全量总结 V0.1

## 1. 目标

Brick Mother 是一个共享形状母体和三套材料规律组成的程序化砖块体系。输入材料、地域、年代、湿度、暴露、批次与种子后，系统生成具有可解释差异的砖块子代。

三类输出：

1. `ADOBE`：土坯砖，可含稻草，允许干缩、雨蚀圆化和纤维脱落孔。
2. `FIRED_CLAY`：烧结砖，稻草严格锁零，颜色和脆性受土源、烧成温度、窑内气氛与批次影响。
3. `STONE`：石块，稻草严格锁零，形态受岩性、晶粒、层理、节理与解理影响。

共享部分包括尺寸、长宽高比例、基础圆角、宏观缺损、孔隙分布、表面噪声、时间入口、地域先验、批次种子和实例种子。材料分支负责把这些通用输入转译为各自可信的物理结果。

## 2. 已完成的知识结构

### 2.1 形状层

- 尺寸与微观尺度解耦，修改砖块大小不会按比例放大砂粒、孔洞和稻草。
- 大崩角、断裂和轮廓损失进入几何层。
- 微孔、砂感、矿粒、窑变和细粗糙度进入材质或着色层。
- 同一母种子可派生材料种子、批次种子和实例种子，便于复现。

### 2.2 材料层

| 逻辑 | 土坯 | 烧结砖 | 石块 |
|---|---|---|---|
| 稻草 | 允许 | 锁零 | 锁零 |
| 主要孔洞 | 纤维脱落、团粒与干缩 | 气孔、夹杂剥落、烧成缺陷 | 晶粒脱落、溶蚀与节理空隙 |
| 主要边缘 | 湿干循环和雨蚀圆化 | 脆性崩角和烧成变形 | 解理、层理和颗粒崩落 |
| 颜色来源 | 地方土壤、含水、风化 | 黏土矿物、温度、气氛、批次 | 岩性、矿物、表面风化 |
| 时间反应 | 软化、冲刷、纤维暴露 | 污染、盐析、脆裂、窑色保留 | 氧化、溶蚀、层理剥落 |

### 2.3 时间和地域

- “新房”与“老房”通过年龄、暴露、维护和修补共同决定。
- 地址提供土壤、岩性、降雨、温湿循环和传统工艺的先验分布，并附置信度。
- 烧结砖的颜色还要经过烧成温度、气氛和窑内位置修正。
- 墙体环境中的朝向、檐口保护、近地高度、盐分与水路决定同一批砖的局部老化差异。

### 2.4 数据预算

| 单元 | 目标预算 |
|---|---:|
| 母体核心参数与规则 | 压缩后 50 至 100 KB |
| 单个地域配置 | 1 至 5 KB |
| 单个墙面分区 | 100 至 500 bytes |
| 默认单砖持久数据 | 0 bytes，通过种子重建 |
| 少量英雄砖例外数据 | 16 至 32 bytes |

此预算不含 Three.js 等网页框架依赖。生产运行时应优先共享几何、实例化渲染和确定性种子，避免为每块砖保存独立网格与纹理。

## 3. 已完成的可视化原型

在线地址：<https://brick-mother-nest.sunhaihao.chatgpt.site>

当前网页实际生成 9 个三维对象：

- 土坯子代 3 个
- 烧结砖子代 3 个
- 石块子代 3 个

交互功能：

- 鼠标拖动旋转，滚轮缩放。
- 点击单砖查看材料规则、尺寸、种子和持久数据预算。
- 按全部、土坯、烧结砖、石块筛选。
- 年代、湿度、批次差异三个连续控制量。
- “再生一窝”更新母种子，并确定性派生九个子种子。

实现特点：

- 运行时不加载原砖纹理。
- 运行时不依赖用户参考 GLB。
- 颜色、粗糙度、孔洞、稻草和部分轮廓扰动由代码生成。
- 土坯分支生成稻草，烧结砖和石块分支不会生成稻草。

## 4. 当前视觉证据

1. `evidence/brick-mother-v0.1-visual-board.png` 提供九砖整体视觉方向。
2. 在线网页提供可旋转的真实程序化三维原型。
3. 生产构建与在线部署均成功。

视觉板属于方向图，同组三个面尚未由同一三维实例和同一固定种子自动渲染。网页端也还没有生成逐资产三视图截图、深度图、法线图和参数回执。

## 5. 生产线判定

### 可直接进入研发生产线

- 三种材料的分类和互斥规则。
- 母种子、材料、批次、实例的层级设计。
- 年代、湿度、地域、暴露和维修的参数入口。
- 零单砖持久数据的默认策略。
- 九砖并排快速迭代网页框架。
- 土坯稻草与另外两类稻草锁零规则。

### 需要修改后进入资产生产线

- 圆蚀边缘需要真正改变轮廓和曲率连续性，减少贴附小球式视觉。
- 层状侵蚀需要沿沉积层或解理面形成有方向的退界和台阶。
- 土坯孔隙、烧结气孔、石块晶粒脱落需要独立的尺度分布和截面形态。
- 表面随机性需要低频、中频和高频分离，并建立尺寸不变的物理尺度。
- 同一资产三视图需要固定种子、固定灯光、固定相机和统一标尺。
- 参考 GLB 需要提取包围盒、三角形数、UV、材质槽、轴向和单位信息。
- 浏览器需要完成桌面和窄屏截图、交互、控制台、WebGL 和性能证据。

### 暂缓进入云南建筑最终生产线

- 当前砖块几何还缺少参考资产蒸馏后的比例统计。
- 当前侵蚀、断裂和层理效果仍处于视觉原型阶段。
- 墙体中的石基衔接、灰缝、内外抹灰覆盖和排水路径尚未接入本分支。
- 地域颜色模型还没有以云南土壤、岩性和烧成样本建立校准范围。

## 6. 推荐下一阶段

1. 只读解析六个 GLB，建立尺寸、比例、拓扑和材质结构报告。
2. 从参考资产提炼统计分布，禁止把原纹理带入运行时。
3. 建立同一子代三视图流水线，每种材料生成三个子代，每个子代输出正、侧、顶三面。
4. 改造几何内核，优先完成真实崩角、圆蚀轮廓和层状侵蚀。
5. 建立浏览器视觉 QA，保存截图、参数 JSON、控制台日志和性能指标。
6. 视觉通过后再接入墙体、石基、灰缝和抹灰系统。
