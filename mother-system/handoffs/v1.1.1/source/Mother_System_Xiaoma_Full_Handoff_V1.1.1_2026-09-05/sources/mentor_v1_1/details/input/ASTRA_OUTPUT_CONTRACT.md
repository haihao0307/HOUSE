# Astra Output Contract

Please return your work as a structured research package, not a chat response.

## Required files

1. EXECUTIVE_ASSESSMENT.md
2. ARCHITECTURE_RECOMMENDATION.md
3. LEARNING_LOOP_SPEC.md
4. VISUAL_OBSERVATION_AND_SHAPE_DISTILLATION.md
5. MATERIAL_AND_PHYSICS_MODEL.md
6. MEMORY_ARCHITECTURE.md
7. WORLD_EVIDENCE_AND_PROVENANCE.md
8. RESOURCE_MAP.md
9. CRITIQUE_AND_RISK_REGISTER.md
10. ROADMAP.md
11. MOTHER_UPGRADE_ACTIONS.md
12. OPEN_QUESTIONS.md
13. HANDOFF_TO_XIAOMA.md
14. CHANGELOG.md

## Required properties

Every recommendation should include:
- problem being solved,
- reasoning,
- evidence or reference basis,
- alternatives,
- risk,
- implementation priority,
- which Mother(s) it affects,
- how to test it.

## Evidence discipline

Mark every important statement as one of:
- ESTABLISHED
- STRONG_INFERENCE
- PROPOSAL
- SPECULATION
- OPEN_QUESTION

## Resource map

For each resource:
- name
- type
- domain
- why it matters
- what to learn from it
- what not to copy
- priority
- source link
- expected learning payoff

## Mentor memory

HANDOFF_TO_XIAOMA.md must be sufficient for the next mentor consultation to resume from the current state without restarting from zero.

It should include:
- what you understood,
- decisions you recommend,
- unresolved disagreements,
- unresolved questions,
- resources assigned,
- what should be tested before the next consultation.

## Format

Markdown first.
Use tables only where they improve comparison.
Keep raw URLs in SOURCE_MAP.md or RESOURCE_MAP.md.
Avoid dependence on proprietary binary formats.
