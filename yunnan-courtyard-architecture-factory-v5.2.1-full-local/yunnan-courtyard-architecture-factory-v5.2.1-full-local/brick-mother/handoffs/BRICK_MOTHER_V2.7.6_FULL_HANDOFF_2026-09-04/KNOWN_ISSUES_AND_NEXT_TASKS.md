## 2. 当前未关闭的问题

### 2.1 V2.7.5 启动速度

软件渲染浏览器记录：

1. 综合工作台外壳就绪约 720 ms。
2. 真实 V2.7.5 主样本就绪约 13.6 s。
3. Canvas 和运行时最终正常，运行时身份为 `2.7.5-alpha.1`。

现有诊断说明主要耗时来自程序化几何和材质的主线程串行生成。当前“快开”只是减少首屏加载范围，还没有完成 Worker 和几何缓存。

### 2.2 PBR 材质真实性

两个实验页面均保留研究价值，也都存在明显视觉问题：

1. Base Color、Roughness、Height、Normal 和 AO 的材料事件关联仍不充分。
2. 砖面微观噪点曾压过宏观与中尺度事件。
3. 石材岩性、断裂面、层理、矿物域与建筑加工形态尚未形成统一体系。
4. 日光实验的环境与展台曾出现黑背景、低照度和错误反射关系。
5. 当前实验均不能替换 V2.7.5。

### 2.3 建筑石材知识

下一轮还需要把石材知识整理成三条独立轴线：

1. 母岩与岩性。
2. 加工与砌筑形态。
3. 建筑部位与使用状态。

优先样本包括方整石、粗加工块石、层状毛石、不规则毛石、片石和建筑卵石。形体需要先用中性灰模验收，再进入材质阶段。

## 3. 下一轮执行顺序

### 阶段 A：重新确认交接包身份

1. 读取本交接目录的五个核心文件。
2. 重新查询远端分支 head。
3. 核对 PR #15 继续保持 open、Draft、未合并。
4. 核对三个冻结文件的 Git blob。
5. 核对综合工作台公开地址仍能访问。

### 阶段 B：建立独立性能候选

1. 复制 V2.7.5 运行时所需 HTML 与 JS，建立版本化性能候选。
2. 保持种子、参数、几何输出、相机、灯光和材质输出一致。
3. 把 `buildMesh()` 移入 Web Worker。
4. 使用 Transferable ArrayBuffer 传递 positions、normals 和附加属性。
5. 主样本完成后立即显示，其他家族按需生成。
6. 为生成几何建立 IndexedDB 确定性缓存。
7. 缓存键必须包含运行时版本、profile、全部种子、几何 controls、质量等级和算法版本。
8. 静止时停止无意义的连续渲染。
9. 阴影只在几何、灯光和镜头改变后更新。

### 阶段 C：性能对照门

1. 原 V2.7.5 与性能候选使用相同参数和相同种子。
2. 检查顶点数、索引数、包围盒、事件统计和渲染输出身份。
3. 桌面和移动设备分别记录首屏、主样本、完整家族和交互时间。
4. 任何通过降低材质或几何质量获得的速度提升都判为失败。

### 阶段 D：建立材料事件图

1. 先只做一块烧结砖候选。
2. 定义黏土母体、砂粒夹杂、压制、切割、烧结梯度、玻化、气孔、崩角、剥片、裂纹、粉化、积尘和湿润事件。
3. 每个事件共享一个空间来源。
4. 每个事件分别向 Base Color、Roughness、Height、Normal 和 AO 输出符合物理职责的响应。
5. Metallic 固定为 0。
6. 常见介电 F0 默认使用 0.04，只有实测依据才能调整。
7. Base Color 不包含宏观照明与 AO。
8. AO 只影响环境漫反射可达性。
9. Height 负责低频和中频形体。
10. Normal 负责高频细节。

### 阶段 E：固定灯光检查

一个 PBR 候选需要经过以下四种固定条件：

1. 中性材质检查棚。
2. 明亮日光展示棚。
3. 掠射光检查。
4. 阴天柔光检查。

四个条件使用固定白平衡、曝光、相机、画面占比和色调映射。

### 阶段 F：建筑石材灰模

顺序固定为：

1. 层状毛石。
2. 片石。
3. 建筑卵石。
4. 方整石。
5. 粗加工块石。
6. 不规则毛石。

每个家族先通过比例、承重面、接触稳定性、断裂方向、层理和边缘锋钝检查。

## 4. 发布门

新候选发布前必须同时满足：

1. 冻结核心字节级不变。
2. 自动技术检查通过。
3. 同镜头对照显示明确进步。
4. 中性光、日光、掠射光和阴天光全部通过。
5. 移动端可操作。
6. 人工视觉批准仍由用户亲自给出。
7. `humanVisualApproved` 与 `productionApproved` 在批准前保持 `false`。
