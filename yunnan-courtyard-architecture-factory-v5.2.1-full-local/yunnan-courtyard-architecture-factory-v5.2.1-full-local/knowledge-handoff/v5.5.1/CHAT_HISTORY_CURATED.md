# 用户与小李工程师的有效对话记录

本文只保存对项目继续工作有价值的对话结论、建筑判断、纠错意见、工作方式和验收标准。寒暄、重复确认、临时等待、失效链接、缓存路径、工具报错和无效中间状态不进入本文。

## 一、项目总目标

用户要建立一套可以持续扩展的云南民间建筑生产线。

这套系统必须具备以下能力：

1. 从平面图、地基、柱网和间架开始生成建筑。
2. 严格按中国传统建筑的开间、进深、楼层、剖面、梁架、檩椽和屋面逻辑推进。
3. 把滇中一颗印、纳西民居及后续地方支系放入同一母系统，同时保留各支系特征。
4. 将测绘资料、历史图录、实拍照片和 GLB 样板模型转换成版本化知识合同。
5. 让知识真正作用到完整建筑生成器和公开网页。
6. 用户通过网页直接观察成果，再提出下一轮修改。

## 二、用户指定的协作方式

用户称总设计与审查助手为“小李工程师”。

小李工程师负责：

1. 先读取 GitHub 知识库和现有代码。
2. 整理资料之间的证据关系。
3. 把任务拆解并直接交给 Codex。
4. 审查 Codex 的远端实际提交。
5. 运行浏览器测试和建筑专项验收。
6. 合并通过的版本并发布网页。
7. 向用户只展示可以直接观察的网页成果。

Codex 负责实际代码、数据、测试和网页实现。Codex 的本地摘要、本地提交号和无法读取的容器路径不算交付。GitHub 远端必须能读取真实文件。

用户不承担以下中间操作：

1. 给 Codex 复制任务。
2. 传递参数表。
3. 下载并重新上传项目文件。
4. 手工拖入已有参考模型。
5. 处理 Git 分支、PR、Pages 和测试配置。

用户只负责看网页、检查建筑和提出反馈。

## 三、知识库优先原则

用户多次强调：每次开始工作前都必须先阅读 GitHub 知识库。

执行顺序固定为：

1. 读取 `AGENTS.md`。
2. 读取 `PROJECT_STATE.md`。
3. 读取当前支系、瓦作、墙体、门窗和交通知识合同。
4. 读取相关测绘图、图录关系矩阵和参考模型分析。
5. 运行现有验证和浏览器测试。
6. 确认知识与代码一致后再修改。

禁止 Codex凭想象补齐传统建筑构造。证据不足的参数必须标记为 `unresolved`、`visual-calibration-only` 或相应证据等级。

## 四、平面与建造逻辑

用户要求从建筑平面图开始理解云南建筑。

核心依赖链：

`证据与年代 → 场地与主轴 → 院落拓扑 → 间架与柱网 → 地基与墙脚 → 一层平面 → 楼面与二层 → 立面等级 → 控制剖面 → 木构装配 → 屋面与瓦作 → 门窗运动 → 历史状态 → 三维装配与验收`

必须遵守：

1. 平面没有通过，立面和三维不能继续。
2. 柱网、墙体、楼面、屋架和屋顶共用同一组轴线与标高账本。
3. 建筑用开间数量组织，不以任意零散部件作为生成基础。
4. 单排主体建筑采用双坡屋面。附属廊厦可以采用有证据支持的披檐。
5. 主体屋面按单体独立生成，不能把整个院落合成一张连续屋顶。

## 五、滇中一颗印的空间知识

一颗印典型格局为“三间四耳倒八尺”。

空间组成：

1. 正房三开间。
2. 左右耳房各自组织楼层和屋面。
3. 入口倒座。
4. 中央天井。
5. 正房大厦及耳房、倒座小厦。
6. 楼梯位于正房与耳房转角的交通区域。

用户要求所有空间关系先在平面图中清楚表达，再逐层生成地基、墙体、楼面、木构和屋顶。

当前测绘控制数据包括正房面宽、总进深、三间面阔、天井、楼面、檐口、檩位和屋脊标高。具体数值以仓库中的一颗印测绘 JSON 和系统合同为准。

## 六、纳西支系知识

纳西支系包含：

1. 一坊房。
2. 两坊拐角。
3. 三坊一照壁。
4. 四合五天井。

单体类型与院落类型分开管理。单体类型包括平房、明楼、两步厦、两面厦、蛮楼、闷楼和骑厦楼。

纳西民居重点特征包括悬山、厦子、悬鱼、瓦猫、小青瓦、麻雀台和金包玉。测绘尺度不足时只生成类型语法，不编造米制尺寸。

## 七、板瓦、筒瓦与屋面构造

用户反复指出，瓦作是当前系统最关键的错误来源。

### 7.1 固定拓扑

1. 板瓦凹面向上，沿最大坡降方向形成连续水槽。
2. 筒瓦凸面向上，覆盖相邻两列板瓦之间的纵缝。
3. 板瓦列与筒瓦列不能使用相同数量简单复制。
4. 板瓦檐端连接滴水。
5. 筒瓦檐端连接勾头。
6. 瓦从檐口向屋脊铺设，上段压住下段。
7. 正脊、垂脊、封头和脊部装饰在坡面瓦完成后单独装配。

### 7.2 用户对 V5.5 的明确纠错

1. V5.5 中板瓦和筒瓦排布错误，需要回查刘致平图录和知识合同。
2. 中央最高脊瓦和正脊必须位于两坡最高交界轴线。
3. 瓦需要伸出墙体，檐口应看到板瓦与筒瓦端部层次。
4. 山墙只能位于双坡屋面的两个山面端部，不能放到建筑后方成为独立高墙。
5. V5.4 的部分瓦作关系比 V5.5 更接近正确方向，修正时应保留其中正确关系。
6. 主界面不再显示旧版 A/B，用户只看最新版本。旧版只能留在后台做回归。

### 7.3 历史瓦面

用户提供的实拍照片显示：

1. 瓦列具有手工微差和连续沉降。
2. 檐口不形成机械直线，瓦端有轻微长短差、下沉和破角。
3. 筒瓦高度、口径、烧成色和旧化程度存在连续变化。
4. 青灰、暖灰、褐灰、灰白和局部土黄色共同形成综合色。
5. 灰尘积聚在筒瓦顶部、搭接处、低洼和背风位置。
6. 苔藓和地衣集中在阴湿、水流慢和遮蔽区域。
7. 雨蚀沿坡向形成连续水路。
8. 破损、缺瓦和修补以片区出现，不做逐片独立白噪声。
9. 屋脊、檐口、转角和不同屋面交接处具有更复杂的手工收口。

## 八、墙体生产知识

用户要求墙面形成独立生产系统，并与砖石、木作、门窗系统组合。

### 8.1 墙体层级

1. 土墙或夯土主体。
2. 抹灰层。
3. 稻草纤维、砂粒和粗颗粒。
4. 雨蚀后裸露的土坯或夯土基层。
5. 石勒脚或砖墙脚。
6. 砖包角与洞口保护。
7. 返潮、雨痕、剥落、裂缝和修补层。

### 8.2 大理案例带来的关键知识

1. 保存较好的墙面仍能看到抹灰中的稻草纤维和细小颗粒。
2. 雨水侵蚀后会露出土坯或土砖。
3. 土砖颜色有深有浅，边缘自然破碎。
4. 抹灰脱落边缘应有厚薄过渡，不能用随机多边形色块代替。
5. 夯土墙可见水平层带、手工抹压和粗粒夹杂。
6. 墙脚、转角、洞口和材料交界处的风化强度不同。
7. 返潮从墙脚向上衰减，雨痕服从重力和檐口遮蔽。
8. 修补区域具有边界、材料差和年代色差。

## 九、砖石与墙脚

需要分别生成和管理：

1. 石勒脚。
2. 砖墙脚。
3. 砖包角。
4. 门洞和窗洞边缘保护。
5. 局部砖砌修补。
6. 土墙与砖石交界。

墙脚污染、返潮和泥溅从地面向上衰减。砖石边角允许磨损、缺角和旧色差。

## 十、门窗与木作

门窗必须具备宿主墙、洞口、框、扇、转轴、开启角和状态。

门窗、柱、梁、枋、栏杆和门楼木作使用同一套历史表面生产逻辑：

1. 木材基础色和木纹方向。
2. 日晒褪色。
3. 雨淋发灰和返潮发暗。
4. 常触摸区域包浆。
5. 边角磨损和局部开裂。
6. 修补或替换件的年代色差。

门窗不能作为贴在墙面的装饰片。

## 十一、人物入户和上楼

人物交通顺序：

1. 门外主轴。
2. 大门自动开启。
3. 穿过倒座门道。
4. 进入中央天井。
5. 沿小厦檐下通道转向楼梯巷。
6. 登上 8 加 8 级双跑木梯。
7. 到达二层大厦或檐廊。
8. 二层房门自动开启。
9. 进入二层空间。

验收要求：

1. 人物不穿墙。
2. 人物不穿楼板。
3. 门洞、栏杆和楼梯碰撞正确。
4. 二层标高以当前测绘账本为准。
5. 镜头支持外部第三人称、院内跟随和人眼入户。

## 十二、三个参考 GLB 的证据用途

### 12.1 大理参考模型

用于：

1. 多层屋面群的高差和遮挡。
2. 屋面可见厚度和檐口层次。
3. 墙面大尺度综合色层。
4. 石脚、砖角和边缘保护。

限制：不能从扫描外观推定精确瓦片搭接、隐蔽基层、墙体内部构造或普通住宅脊部节点。

### 12.2 乌龙村参考模型

用于：

1. 瓦面凹凸和粗糙度。
2. 灰尘、苔藓、雨蚀、破损和修补。
3. 墙皮剥落、返潮、污渍和修补。
4. 底色贴图和法线贴图的综合色。

### 12.3 团结乡参考模型

用于：

1. 屋顶、一层、二层、场地和细部分组。
2. 院落尺度和空间关系。
3. 墙体、木构和屋面相邻关系。
4. 人物入户和楼层交通校准。

## 十三、网页与显示要求

1. 网页打开后直接显示完整建筑。
2. 建筑完整进入镜头，不被界面裁切。
3. WebGL 深度测试正确，旋转时不能穿面。
4. 支持完整建筑、屋顶俯视、檐口、正脊、山墙、墙脚、门窗和楼梯近景。
5. 支持屋面爆炸、单坡隔离、水流和证据状态观察。
6. 主界面只显示最新版本。
7. 用户不看参数说明页作为最终交付。
8. 每轮完成后都要推入 GitHub，再由 Pages 更新公开网页。

## 十四、用户验收习惯

用户会重点检查：

1. 板瓦与筒瓦关系。
2. 正脊和脊瓦位置。
3. 檐口出挑和端部厚度。
4. 山墙位置。
5. 瓦面是否过度整齐。
6. 墙面是否仍像平面色块。
7. 土坯、抹灰、稻草、返潮、雨痕和修补是否自然。
8. 木作是否具有年代感。
9. 人物能否顺利入户并上二楼。

出现结构性错误时，应先停止继续装饰，回到知识库和测绘逻辑修正。
