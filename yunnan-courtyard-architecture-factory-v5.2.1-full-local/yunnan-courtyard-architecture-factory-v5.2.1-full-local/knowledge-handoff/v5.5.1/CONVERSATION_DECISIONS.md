# 用户与小李工程师的关键对话决策

## 工作方式

- 小李工程师负责总设计、知识审查、Codex 指挥和最终验收。
- Codex 是执行助手，必须把实际文件提交到 GitHub，不能只报本地提交号或写总结。
- 每个任务开始前先查 GitHub 知识库，读完知识合同和测绘资料，再修改。
- 用户不负责传文件、复制任务、下载本地包、拖放模型或填写参数。
- 用户只看网页成果。中间过程、参数表和配置不作为交付。
- 完成的新知识必须进入 GitHub 数据合同和主生产线，不能停留在孤立知识页。

## 版本与展示

- 主网页只显示最新成果。
- 旧版本只在后台用于回归，不占据主界面或干扰用户判断。
- 版本号必须和实际成果对应，禁止继续沿用上一版编号。

## 平面与建造顺序

- 从平面图、地基、柱网开始，一层一层往上推。
- 严格服从中国建筑的间架、柱网、楼层、剖面和屋面逻辑。
- 旧错误知识应清理，宁可慢一些，也要一次做对。

## 瓦作反馈

- V5.5 中板瓦和筒瓦排放关系错误，必须回查知识库和图录。
- 正脊或中间最高脊瓦位置必须沿两坡最高交界。
- 瓦片要出到墙外，形成真实檐口层次。
- 山墙不能错误地放在建筑后部，只能出现在双坡屋面两端。
- 历史瓦面不能过于整齐，需要沉降、错位、灰尘、日晒、雨蚀、苔藓、破损和维修片区。

## 墙面反馈

- 大理案例显示完整抹灰、稻草纤维、粗粒土体和被雨水侵蚀后露出的土砖。
- 土砖有深浅和自然边缘，抹灰脱落不能是随机多边形色斑。
- 墙、砖、石勒脚、包角、门窗和木作应分别建立生产系统，再组合。

## 模型参考

- 大理 GLB 用于屋面群层级、可见厚度、墙面综合色层和石砖边缘保护。
- 乌龙村 GLB 用于瓦面凹凸、灰尘苔藓、墙皮剥落、返潮和修补。
- 团结乡 GLB 用于屋顶、楼层、场地和细部分组，以及入户交通尺度。
- 扫描模型不能覆盖测绘尺寸或反推隐蔽构造。

## 交付标准

- 打开网页直接看到完整建筑。
- 旋转时遮挡正确。
- 门窗自动打开，人物能入户并到二层。
- 提供檐口、正脊、山墙、墙脚、门窗木作近景。
- 浏览器 QA 和完整生产线回归需要零失败，截图来自真实渲染。
