# V5.5.0 云南墙面与瓦顶生产化审计

## 目标

V5.4.4 已经把大理、乌龙村、团结乡三个真实参考模型的视觉知识、屋面层级、入户交通、墙面预设和瓦顶预设写入数据合同，并通过真实浏览器验收。V5.5.0 必须把这些知识接入正式的一颗印 Three.js 生成器，让用户在民间建筑生产线中直接看到完整建筑的墙体与瓦顶改善。

## 当前正式代码的主要问题

### 1. 瓦件仍受旧视觉参数驱动

`threejs/YunnanCourtyardProduction.js` 的 `YUNNAN_COURTYARD_DEFAULTS` 仍保存：

```text
tileWidth: 0.28
tileLength: 0.64
tileCourse: 0.46
tileThickness: 0.055
```

这四个参数属于旧视觉兼容配置。正式生成应按 `tileProfileId + evidenceStatus` 读取 V5.4.2 和 V5.4.4 合同。

### 2. 板瓦与筒瓦拓扑仍有旧错误

当前 `addRoof()`：

- 板瓦和筒瓦使用相同的 `across` 数量。
- 筒瓦沿坡向使用 `tileCourse * 0.23` 无证据偏移。
- `tileCourse` 同时承担露明量、搭接和排布距离，证据来源不清。
- 没有真实滴水、勾头、正脊、垂脊、封头和排水路径对象。
- 每片瓦都是独立 Mesh，完整院落面数与 draw call 成本过高。

### 3. 屋面仍缺少生产级厚度分层

当前 `roof-deck-underlay` 是一块使用木材材质的薄板。正式屋面需要分离：

1. 檩条和椽列
2. 椽上基层
3. 板瓦水槽
4. 筒瓦盖缝
5. 勾头与滴水
6. 正脊、垂脊和封头

各层必须有独立语义 ID、显隐和证据状态。

### 4. 屋面单元层级尚未完全接入生成器

标准院落必须明确保存：

- 正房对称双坡
- 左耳房内长外短双坡
- 右耳房内长外短双坡
- 倒座独立双坡
- 正房大厦披檐
- 耳房与倒座小厦披檐
- 门楼小屋面

每个单元都需要自己的屋脊标高、檐口标高、坡向、出檐、排水目标和风化参数。不得用统一屋顶参数覆盖全部单元。

### 5. 瓦色仍是通用噪声

`threejs/YunnanMaterialFactory.js` 当前 tile shader 只使用两层噪声混合冷灰与暖灰。它还没有真实表达：

- 烧成基础色
- 坡面朝向与日晒
- 屋脊和檐口附近积尘差异
- 苔藓与长期湿润区
- 顺坡雨蚀
- 缺瓦与破损
- 不同年代修补瓦
- 同一修补片区内部的综合色差

颜色变化需要空间相关，不能让每片瓦完全随机。

### 6. 墙面仍是通用世界坐标噪声

当前 wall shader 只有 macro、meso、fine 三层噪声和简单高度遮罩。它没有区分：

- 土体或砌体主体
- 表面抹灰
- 裸土暴露
- 石勒脚或砖墙脚
- 砖包角和转角保护
- 墙脚返潮
- 檐口遮蔽
- 垂直雨痕
- 表层剥落
- 裂缝网络
- 历次修补斑块
- 烟熏和污渍

正式墙面应把结构、材料和历史状态分层，可独立关闭和回滚。

### 7. 用户目前只能看工具样板，还看不到正式建筑改善

V5.4.4 的理解页已经证明参数和知识关系。V5.5.0 需要把相同数据接到正式建筑，并提供以下可见比较：

- 原始 5.4.4 外观
- V5.5.0 生产外观
- 仅墙面改善
- 仅瓦顶改善
- 完整历史状态
- 墙体与瓦顶诊断分层

## 强制实施边界

1. 平面、柱网、楼层、剖面和屋面单元几何优先于材质外观。
2. 扫描模型只校准可见外观，不覆盖测绘尺寸和隐蔽构造。
3. 风化必须服从重力、日晒、雨水、坡向、檐口遮蔽和修补逻辑。
4. 随机种子必须稳定，同一建筑刷新后保持一致。
5. 墙面与瓦顶参数必须来自版本化 JSON，不允许只存在于 UI 或 shader 常量中。
6. 所有改善必须能够一键关闭并回到 V5.4.4 基线。
7. 三个网页参考模型、人物入户、门窗、8+8 双跑楼梯和 GitHub 同步中枢不得回归。
