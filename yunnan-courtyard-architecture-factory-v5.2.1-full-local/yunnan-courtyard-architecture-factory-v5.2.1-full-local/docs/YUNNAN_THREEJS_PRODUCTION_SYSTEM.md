# 滇中合院 / 团结乡 Three.js 生产体系

## 目的

团结乡高精度扫描只作为“真实外观和构造关系”的参考层。本体系把它拆成可改的 Three.js 源模块，接入滇中一颗印（YKY）母体，避免把一份扫描 GLB 当成生产线唯一输入。

入口文件：

- `threejs/YunnanMaterialFactory.js`：墙体、木作、陶瓦、石作和门洞的 PBR 基础材质与程序化风化层。
- `threejs/YunnanCourtyardProduction.js`：收分墙、山墙、逐片板瓦/筒瓦、木门洞、围廊圆柱、柴屋、石板和日常楼梯。
- `threejs/yunnan-courtyard-production-demo.html`：可拖拽检查的 Three.js 生产原型。
- `data/production/yunnan_threejs_production_system_v5_4_0.json`：资产契约、证据边界和质量门。

## 从案例提取的空间语法

采用“方形边界 + 中心天井 + 正房中轴 + 两侧耳房 + 前方倒座/门廊”的一颗印母体。正房屋脊最高，耳房略低；楼层之间用木梁架和木质围廊分隔。围合外墙高耸、少开窗，主要保留小而高的窗洞；采光、排水、通风和日常活动集中到天井。正房、耳房朝天井一侧挑出腰檐，转角以单跑日常楼梯连接楼层。门前低矮体量可表达柴屋、畜厩或储藏房。

这是布局和比例规则，不是把团结乡扫描包围盒当成实测尺寸。当前模块用已有 YKY 三开间测绘数据作为可替换的比例种子，团结乡的绝对尺寸等待校准图或测量控制点。

## 墙体生成

墙体不是贴图平面，而是带真实收分的棱柱。底部厚度大于顶部，墙脚接石基；山墙用独立三角体量闭合屋架，门洞在墙体中留下深色凹口，不能用悬空门片或贴图补丁代替。

`createWeatheredEarthWallMaterial()` 的颜色和噪声分四层：

1. 暖红土黄的主体底色；
2. 中尺度浅灰白暴露斑，模拟夯土颗粒和风化剥蚀；
3. 低位、沿高度方向变深的雨流/污渍；
4. 细颗粒变化，避免平面塑料感。

这些是用户确认的外观语言。土壤配方、修缮年代、不可见内层没有被假设。

## 云南板瓦—筒瓦

屋面由木质基层和独立陶瓦片组成。每个课程先放承水的凹板瓦，再以错缝和小幅搭接放凸筒瓦；每片网格带有 `course`、`roofSide`、`tileIndex` 和证据规则，方便后续改成真实尺寸、搭接和收头。瓦色是低饱和冷灰与暖灰的程序化混合，粗糙度较高，檐口保留一片片陶瓦的颗粒边缘。

当前禁止把连续 corrugated/metal sheet 当作瓦顶。瓦的宽、长、截面、搭接、泥灰坐浆、脊和边角仍是锁定项，除非用户提供新的标定资料。

## 木作、门窗、柴屋和楼梯

- 外墙外侧不裸露木柱；可见的木作集中在朝天井的围廊、门框、檐下和室内分隔。
- 柱子使用圆木柱；梁、枋、扶手使用低饱和灰棕到深棕的哑光旧木材。
- 门洞有厚度、门框、门楣、两扇板门和面板凹凸；窗户只在外墙设置少量小而高的洞口。
- 门前柴屋是低于正房的独立低体量，屋顶同样由逐片瓦组成。
- 楼梯按可日常使用的踏步、踢面和扶手生成，不使用过陡的“木匠梯”。
- 院地和门前台阶使用不规则石板，石脚与土墙形成湿气和时间的过渡层。

## 证据与质量门

每个对象带 `userData` 追溯字段：分支、模块类型、证据规则、可编辑源文件和未测量状态。生产前必须通过：收分墙可见、墙面有分区风化、瓦片独立且板瓦/筒瓦关系清楚、圆柱、真实门洞、少量高窗、低矮柴屋、日常楼梯、石板台基、未测量尺寸不冒充实测。

扫描 GLB 仍可用于对照颜色、残破程度和空间关系；生产线使用的是本模块的可编辑源模型，后续可以按新测绘图替换参数和局部构件。
