# 单片板瓦：函数、变量、造波 R01

已完成单片无纹饰板瓦的连续函数定义分离。不是新的整屋工作台，也不是把网格文件改名为函数。

## 三个组成

1. 函数：pan.function.cjs中的base、skin、hand与shape。包含弧面、收分、厚度变化、端口、边口圆顺和原有手工形变。
2. 变量：pan-L9.json或pan-D7.json。尺寸、种子、形变幅度；身份、坐标、来源与误差同时保留。每个对象引用共同函数版本，不复制函数库。
3. 造波：同一共享文件中的tileBand、offset与displacement。作用于同一局部形体坐标，种子、强度、尺度来自对象wave段，不依赖顶点编号。

pan.function.cjs为5,850字节；L9对象文件为753字节。独立使用时两者共6,603字节，函数库只存一次。此数字不含颜色光照着色器、花纹瓦当和屋面安装求解，也不将共享库成本隐藏成零。

## 直接调用，无需网格

```js
const {createEvaluator}=require('./pan.function.cjs');
const object=require('./pan-L9.json');
const tile=createEvaluator(object);
const shape=tile.shape(0.2,0.4,0);        // 形状函数，含厚度/边口规则
const wave=tile.displacement(0.2,0.4,0); // 该位置的表面造波
const final=tile.position(0.2,0.4,0);    // 最终位置，单位米
```

u为横向[-1,1]，t为纵向[0,1]，q为厚度方向[0,1]。上、下表面分别q=0、q=1；左右侧边u=-1、u=1；前后端面t=0、t=1。它们是同一函数参数域的边界，不是持久保存的三角面。法向沿用09H的局部有限差分求值，不依赖显示采样密度。

为保持09H顺序，程序先在未造波的形体参考点求造波，再组合原有手工形变；没有把示意公式当作可随意交换顺序的近似。handReferenceHalfWidth与handReferenceLength保留09H原归一化参照，不擅自改为当前规格尺寸。种子、尺寸可改变，但未验证参数的任意组合都物理合理。

## 显示层是可选消费者

display-adapter.cjs仅消费函数，临时采样显示；对象和函数均不导入它。删除适配器仍可直接查询形体。它为了对照旧09H，保留旧显示路径的Float32中间舍入；连续定义本身没有这个舍入。

## 验证与边界

运行`node verify.cjs`：L9/D7共8组配置，每组300个参数点（含面、边及厚度内部），与固定09H原始连续规则误差为0；默认两档显示细分及额外造波强度/尺度配置的顶点、法线、索引、参考坐标逐项相等。另检查六个尺寸变量确实改变求值、对象修改不污染已创建求值器、函数无显示依赖。VALIDATION.json记录实际结果。

这证明本次函数分离在所测配置下保留原规则与显示输出，不代表所有参数、实物结构、防水或历史测量验证。它没有新增PBR方案，未替换整屋09H公网页面。固定09H质量锚点继续保留。
