# Tiles Mother · R2 收尾候选 08 · irregular surface

本候选从固定的 R2-closeout-07-detail 源码提交 `dcf4053f69efc031174b7c41bd41e2309dfb13ec` 接续，保留 06/07 旧版，不覆盖历史候选。

本轮只处理用户指出的“表面纹理过于整齐、同一种算法铺满整片瓦”的问题，不改瓦片大轮廓、尺寸、主弧度、厚度、搭接与支承、木构、屋面年份逻辑或交互架构。

核心纠正不是简单增加随机噪声，而是让随机性受成型过程约束：

- 每片瓦继续有稳定 seed / identity，不随镜头或帧变化。
- 增加两层宽尺度、连续的材料区域，先区分压实区、安静区与活跃区。
- 局部材料坐标只做低幅、连续、seed 稳定的 domain warp；方向由片级身份、材料区和既有 ceramicTurn 共同决定。
- 刮抹采用两组不同尺度/方向的 stroke family，并通过压力岛和段落门控形成有限、断续的痕迹，避免单一重复纹理。
- 孔蚀与小凹坑先由区域簇决定，再由细/粗两级孔场生成，并在压实刮抹区主动抑制，避免均匀 pepper noise。
- 粗糙度保持独立场，只接受结构修正，不由 RGB/颜色反推。
- 显示微起伏幅度仍是设计参数，不是从参考贴图反推出的真实毫米测量值。

## 实现方式与边界

`START_HERE.html` 是一个很小的接续加载器：它只读取固定 SHA 的 07 单文件源码，先核对 07 的 `r2Finish` 函数签名，再把这一最终细节函数替换成 08 版本并写回页面。固定源不可变，因此不会悄悄跟随分支漂移；若 07 源函数签名不匹配，加载器会拒绝继续。

这样做用于快速验证 08 的材质方向，同时避免复制/篡改 07 已冻结候选。它不是最终独立封装形式；最终保留候选若视觉通过，应再固化为真正自包含的单文件 HTML。

本地对 08 加载器中的 JavaScript 已执行 `node --check`，语法通过。尚未在真实公网浏览器中完成 fetch、WebGL shader compile、单片/屋面交互、移动端和视觉 QA，因此：

- `browserVerified=false`
- `publicBrowserVerified=false`
- `shaderCompilePassed=false`（尚未真实编译，不以代码目检代替）
- `visualApproved=false`
