# Tiles Mother 09N：共同函数与完整工作台候选

09N以保留09H目录和工作台为起点，继续使用R04的共同基础片、材料参考架、形变及造波。板瓦、筒瓦、三种勾头、两种滴水、D7圆瓦当、正脊中空眼瓦、抱筒、D5折瓦及既有曲脊瓦均由连续规则和配方求值；原有砖、木、梁架、屋面与交互仍保留。范围是09H已有的类型，不是世界所有瓦型。

勾头和滴水的形状按各自来源轮廓与瓦身端口规则建立；圆瓦当的倾斜和尺寸解释仍有未知。复杂纹样以用户提供的L9转发图轮廓作为共享资料，原书版本和实物误差未知。D7也是用户提供的转发测绘图，不能宣称这些模型是实测制造标准或历史施工复原。

几百B是单实例记录、身份与差异引用的概念，依赖不为零。工作台“对象 / 体积”显示当前场景的紧凑记录、共享规则、配方、纹样、连接和新增显示适配器。实际数字见SIZE_AUDIT.json；同屏总览的8个瓦记录为188–278 B，檐口的14个瓦记录为302–421 B，均不含共享形状和轮廓资料。六组纹样共享资料约283,970 B；工作台HTML为1,422,410 B，已经内含运行代码和部分资料。模板、旧版连接/渲染代码与运行内存分别计量，不能把引用字节当作可独立运行的完整瓦。

形体/材料可不依赖网格直接按函数查询；09N为了沿用和提升09H画质，显示时临时采样并生成可丢弃的网格与法线缓冲。这些缓冲不是瓦的持久定义。按相同CSS画幅与同一设备，本机09N画布2400×1350、09H为1920×1080；阴影纹理由1024升至2048。新脊瓦及瓦头另有实际表面位移。画质提升意味着更高显示开销，尚无跨设备性能或真实手机结论。

## 验证范围

- QA09N.json：17个指定场景构建；FOLD_CONTACT09N.json：9场景的默认折坡；SUPPORT09N.json：15场景的名义支承，默认配置按记录中的容差判断。
- JOIN_VALIDATION.json：5种瓦头各405个前端/背面匹配点；数值抽样不等于全部曲面、防水或结构验证。
- RIDGE_STACK_VALIDATION.json：4组强度/尺度各10,000个独立点，检查眼瓦、板层和上层的样本位置。先前高强度出现13.7微米样本穿入，增加0.15毫米求解余量后所测通过；不能推广到所有参数。
- CONTINUOUS_VALIDATION.json：5类形状各90个材料参考测试及205个圆周接缝点；GPU_VALIDATION.json：256个标量造波/颜色/粗糙度对照点。有限测试不能证明全部参数或所有设备一致。
- 本地浏览器按相同初始视角比较09H与09N的檐口、正脊和D5山墙，观察到内容、阴影与显示；这不是逐像素等同或用户视觉验收。图像取舍、真实手机、物理制作和其他未测场景未据此宣称完成。

09H保留为用户认可的质量锚点，09N是待用户观看的候选，不自动取代09H。历史源文件和固定公网链接保留。新版本随包附带项目AGENTS、母体定义、对象定义和公网交付规则；如旧规则文件提示本机可替代公网，以当前项目AGENTS和用户本次固定公网要求为准。
