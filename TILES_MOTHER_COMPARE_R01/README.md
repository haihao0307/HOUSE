# Tiles Mother：同形、同材质 A/B 实测比较 R01

本地/网页比较用自有代码。原 09J、09H、09I、R02 均保留不动。

## 比的是同一完整瓦，不是名称

A：矩形材料片 → 代数高度弯曲 → 梯度法线厚化 → 两侧有效域 → 同一造波材质。
B：直路径 C(s) → 角度圆弧截面 → 径向厚化 → 同一两侧有效域 → 同一造波材质。

两份 shape 源码独立。共同几何约束、材料坐标、TLO、造波器明确共享，计量时全部包含一次。B 的角度是 `theta=asin(k*u*W/2)`，不是 `u*thetaMax`；因此两边同 u 对应同一材料点，不偷换成弧长参数。W 是基础片宽/上表面弦宽，不承诺弯后弧长或泥坯体积守恒。局部原点是未裁切片的材料参考中心，不保证非对称收边后的几何中心。

本例 240×210×14 mm，bend=.45，左右域保留 .94/.88。这里收边是横向域限制，不是纵向收分；完整六边界有厚度实体，未使用网格裁切。材料是自有 sin/cos 多频连续场，作用于同一平片材料坐标，影响颜色/粗糙度；没有图片、外部模型、受限IQ代码或材质几何位移。B 的 sin/cos 圆弧运算不是随机 fBm，未实现/未比较用户尚未给出的通用两波耦合公式。

原样源码仅差11 B；统一格式差9 B。这受命名/排版/实现分层影响，不是算法固有下界或有意义的“哪条路线胜出”。原09J已经融合成圆弧直挤出特例，本次A是明确展开步骤的新比较实现，不拿它的运行速度冒充旧09J速度。

9个变量：L、W、T、bend、左域、右域，共6个几何数；frequency、amplitude、seed，共3个材质数。实际写出的9×float64裸数值为72 B，未含Time/Location/身份/母体引用；不是旧09J四参数float32的16 B。shape+material紧凑JSON124 B，完整TLO236 B，格式/编码不可混计。

正确共享后，N实例成本为共享核一次 + N×实例记录；本例固定宽度唯一ID、相同参数文本长度时，两者增量同为236 B。N=1亿也只差共享核11 B，不是11 B乘一亿。本表明确假设每个实例独立记录这组值；同规格瓦的几何/材质参数组本身也可共享，实例只保身份、位置/状态与必要差异，不必每片重复9值或完整TLO。这项优化同样适用于A/B，不能只算给某一方，也未在此另建场景引擎。

显示另外计：已知两套圆弧函数的边界编译1099 B，解析求交+CPU Worker5506 B，UI/模板13879 B。完整独立双栏HTML包含两母体/共享项/编译/显示/实测数据，见BUILD.json（36337 B）。母体没有隐藏依赖，显示成本也没有消失。

## 等价与测量边界

- 19,800点，位置最大差1.33e-15 m；法线8.62e-16；材料坐标和颜色差0。
- 43,200个实际射线边界/逆材料地址测试通过；独立Worker 5项、实际UI源码契约8项通过。
- 每次参数改变，两份真实TLO各自产生源求值器，再分别由编译器读position/normal导出边界；每边33次显式源API调用（不是87次，也不是所有内部数学调用的计数）。独立Worker分别求帧，未复制同一bitmap。
- 编译器是**这两份已知常圆弧直挤出函数**的特例转换。27个fit点只作回归保护，不能证明任意未知函数都符合圆弧族；不是通用扫掠编译器。
- 两边共用解析求交，因此网页帧耗时不能当两种形体求值器的比较。数学基准单独运行，7轮交替、相同采样、同一CPU；当前完整形体+材质120000次约A20.35/B20.19 ms，区间重叠，不能据此判定本质快慢。
- A写法中有重复检查/sqrt及hypot，B显式角度式有asin/sin/cos；优化融合可以改变此结果，不证明路径形式天生更快/慢。
- 有界10,000项GC后堆增量：仅记录约7.14 MB，缓存A/B完整evaluator约17.75/17.67 MB。后者是可丢的运行时缓存，不是每个对象必须创建一份函数闭包，更不是序列化字节或峰值内存。未生成亿对象，未测GPU内存/手机。

另外只检查原R02 pan-L9一个零细节变端宽案例：宽.21→.19 m、弧高.045→.0423 m、厚.014 m；保留纵向完整表面有限差分法线。A/B 5000点误差0，与原R02差1.55e-17 m；依赖闭包1908/2019 B。该项仅数值诊断，未把它强塞进常截面解析显示，也未拿完整10 KB旧材料库与本特例比。若只沿截面内法线加厚，会漏纵向偏移，独审反例约0.328 mm，不能称同形。
